# The code-fix agent

Plan and design for the component that turns a failed run into a reviewable fix of the store's source. Branch `codefix-agent`. It consumes what is already built (the agent and mission reports, the repository connection) and produces a validated unified diff, optionally pushed to a branch or opened as a draft pull request. It never merges.

Read [ARCHITECTURE.md](./ARCHITECTURE.md) for the run pipeline it sits behind and [storefront/test-site-guide.md](./storefront/test-site-guide.md) Part 2 for the scoring rubric its output is graded against. What it did live, with costs and grader results, is in [CODEFIX-RESULTS.md](./CODEFIX-RESULTS.md).

## 1. What it must do, and must never do

**Does**

- Read the evidence AgentProof already produced for a failed run: the failed checkpoint (code-written), the attribution from the mission report (code-written prior), the failure point with what the agent perceived, the step log, the observed cart.
- Read the connected repository snapshot (the bare, shallow clone from the repository connection) and find the files most likely to hold the cause, by code, before any model sees source.
- Ask a cheap model for a diagnosis and a minimal change, as search/replace edits against the source it was shown. Code turns the edits into a unified diff.
- Validate the diff with code: in scope, no dependency changes, bounded size, applies cleanly to a clean worktree at the snapshot commit, typechecks, and (opt-in) the same agent passes a real rerun against the patched store.
- Optionally ask a second model to review the diff against the evidence and the rules. Its verdict is advisory and labelled as such.
- Deliver as a diff (default), as a pushed `agentproof/*` branch with a prefilled "open a pull request" link, or as a **draft** pull request.
- Record everything: which evidence, which files, every attempt including failed ones, every check with its verdict, tokens and cost, and a timeline. One JSON document, one Markdown rendering.

**Never**

- Merges, approves, or marks a pull request ready for review. Never pushes to the default branch, never force-pushes, never deletes a branch. The GitHub client has an allowlist of operations; a merge call cannot be expressed. Tests assert it.
- Stores or logs a token. Tokens arrive per request, live in memory for that request, and reach git only through the environment (the existing repository connection pattern).
- Runs repository code during connection, localization or validation. The snapshot is bare, files are read with `git show`, the worktree is created with `git worktree`, and `npm ci --ignore-scripts` installs without lifecycle scripts. The only place repository code runs is the opt-in rematch, which boots the patched store as a child process with a scrubbed environment and a timeout.
- Lets the model decide a verdict. Every `status` in the record is written by code. The model's text is in fields named `inferred*`, `proposal`, `review` and is rendered as a hypothesis.
- Shows the model anything outside the store directory in the repository (so never `docs/` in the monorepo, never the answer key).

Why this matters for the Visa track: trust and security are judged. "The agent opened a draft PR you can read in two minutes, every check in the description was run by code, and it could not have merged" is the pitch.

## 2. Modifying GitHub repositories: what exists, and what to use

**What Vihan built** (`apps/runner/src/repositories.ts`, `repository-routes.ts`, `packages/shared/src/repository.ts`): `POST /runs/:id/repository { url, token?, consent }` validates a `https://github.com/owner/repo` URL, clones it bare and shallow into `data/repositories/<id>/`, lists the tree, and saves metadata (never the token). The token is an optional fine-grained PAT with Contents read, passed to git through `GIT_CONFIG_*` environment variables, never argv, never the remote URL, never disk. Hooks are disabled, `file:` and `ext:` protocols are refused, redirects are off, stderr is never surfaced. Routes are localhost-only. The gate requires a failed Gamma run; the code-fix agent needs it opened to any failed run.

**Three ways to get write access**

| Option                         | Permissions                                                                                                 | Identity on the PR                                  | Setup                                                                                          | Verdict                                                                                                                                                           |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fine-grained PAT (per request) | User picks the one repo and the exact permissions: Contents read/write, Pull requests read/write            | The user                                            | None. Extends the connect form with one more scope.                                            | **Build first.** Works today, least code, and least privilege is in the user's hands. Token is memory-only for the request.                                       |
| OAuth App                      | Classic scopes only. `repo` grants every repo the user can reach, read and write, long-lived until revoked  | The user                                            | Register app, client secret, callback URL, browser round trip                                  | **Rejected.** Coarser than a PAT, more moving parts, and the token is a bigger blast radius. Nothing about OAuth makes the no-merge rule stronger.                |
| GitHub App (installation)      | Fine-grained per installation; the owner installs it on exactly the repos they choose; tokens expire in 1 h | `agentproof[bot]`: the agent is visibly not a human | Register app once, keep app id + private key in `.env`, sign a JWT, mint an installation token | **The right long-term answer.** Strongest provenance and short-lived credentials, no user token ever touches the server. Build after the PAT path if time allows. |

Decision, as built: **the GitHub App is the primary identity** and the per-request token is the fallback. The runner loads the app from `.env`: `AGENTPROOF_GITHUB_APP_ID`, `AGENTPROOF_GITHUB_APP_PRIVATE_KEY` (or `_PRIVATE_KEY_FILE`), optional `_SLUG` and `_CLIENT_ID`. The one-click manifest flow at `GET /github/app/setup` writes exactly those lines into `.env` (and makes the file owner-only), so one shared `.env` gives every teammate the same app identity. For every operation it signs a short-lived RS256 JWT (`iat` minus 60 s, `exp` plus 9 min), looks up the installation for the repository (`GET /repos/{o}/{r}/installation`), and mints an installation token scoped at mint time to that one repository and the minimum permissions for the operation: `contents: read` for a clone, `contents: write` plus `pull_requests: write` for a push and a draft pull request (`POST /app/installations/{id}/access_tokens` with `repositories` and `permissions`). Tokens expire in an hour and are never persisted. When the app is not installed on the repository, the request token is used; without either, the clone is anonymous and delivery is refused with the install link. OAuth App not pursued. The client allows exactly these operations: `GET /repos/{o}/{r}`, `POST /repos/{o}/{r}/pulls`, `GET /repos/{o}/{r}/installation`, `POST /app/installations/{id}/access_tokens`, `GET /app/installations` and `GET /installation/repositories`. The last two may carry only `?per_page=<digits>&page=<digits>`. Merging a PR requires `PUT .../pulls/{n}/merge`, which the client refuses by construction.

The Findings step uses that list. `GET /github/app/repositories` asks `GET /app/installations`, mints a token with `metadata: read` and no repository named (so it covers the installation), and pages `GET /installation/repositories`. The panel's first action is "Add AgentProof to your repositories", which opens the install URL; the dropdown is the repositories that come back. Connecting one starts the usual diff fixes and, once they validate, the same pull-request request the Fixes step's button sends, so the draft pull requests open without another click. A repository URL and token stays on that panel as the secondary path. That path does not open pull requests on its own, because its consent says nothing is written. The code-fix pipeline is unchanged.

Setup, once per team: start the runner, open `http://localhost:4000/github/app/setup`, click the one button (GitHub shows the permissions and asks where to create the app), and GitHub returns to the runner, which writes the credentials into `.env`. Share that `.env` the way the model key is shared. Then install the app on the repositories AgentProof may work on (the callback page links there; `GET /github/app` reports the install URL). The app is private to the account that registered it, has no webhook (GitHub refuses a non-public hook URL even when inactive, so the manifest carries none), and asks for Contents and Pull requests (read and write) and Metadata (read).

Pull requests are opened as **drafts**. GitHub will not merge a draft until a human marks it ready, so the "a human must act first" rule is enforced by GitHub, not only by us.

## 3. The pipeline

Each stage writes into the same `CodeFix` document and publishes a `CodeFixEvent`, so a frontend can show a live timeline or poll.

```
collect   ->  localize  ->  propose  ->  validate  ->  review  ->  rematch (opt-in)  ->  deliver
(code)        (code)        (model)      (code)        (model)     (code + real run)      (code)
```

1. **collect.** Load the run, mission, agent report, mission report and the connected repository. Pick the first failed checkpoint. Build an `EvidenceBundle` from fields that already exist, nothing raw: mission requirements; checkpoint id and its code-written `detail`; the attribution for that checkpoint (category, reason, pass/fail pattern across agents); the failure point (step, attempted action, outcome, the capped perceived excerpt); one line per step via `summarizeStep()`, at most 30 lines centred on the failure; the observed cart; for Gamma the catalog record and cart response. Rendered as text and capped at about 9,000 characters. The exact text is stored in `input.evidenceText` so a reviewer sees what the model saw. No screenshots, no traces, no full snapshots.
2. **localize.** From the bundle, derive weighted search terms: product slug and name tokens, variant ids, required attribute keys and values, the accessible names the agent looked for (`Add to cart`, `Size`, `Increase quantity`), and category keywords (`aria-hidden`, `role=`, `aria-label`, `<label`, `<fieldset`, `hidden`). Read candidate source files from the bare snapshot with `git show HEAD:<path>` (store root only; `src/**` with a source-extension allowlist; no `node_modules`, `public/`, lockfiles, images). Score every file by term hits, rank, and send the top files in full within a character budget (default 4 files, 14,000 characters); the rest appear as path plus export outline. The ranked list with matched terms is stored, so the UI can show "why these files".
3. **propose.** One `getLlm()` call on the `codefix` role (Haiku by default; `AGENTPROOF_MODEL_CODEFIX=claude-sonnet-5-5` to upgrade). Strict JSON: a diagnosis (title, category, inferred cause, confidence), `edits` as `{ path, search, replace, reason }` where `search` is an exact unique substring of the file shown, and a one-paragraph PR summary. If the model needs a file it was only shown as an outline it returns `needsFiles` instead of edits, and the loop sends those files once. Code applies the edits (exact, unique match or the attempt fails with a precise reason) and generates the unified diff. No model ever writes hunk headers.
4. **validate.** Code only, in order, stopping at the first failure that makes later checks meaningless: `paths_in_scope`, `no_dependency_changes`, `size_within_bounds`, `applies_cleanly` (`git apply --check` in a fresh worktree at the snapshot commit), `typecheck` (`npm ci --ignore-scripts` then `tsc --noEmit` inside the store root; `skipped` with a reason when the repo has no lockfile or tsconfig or the install exceeds its timeout). A failed attempt's check details are fed back to the model for one more attempt (`maxAttempts`, default 2). Every attempt stays in the record.
5. **review** (optional, on by default). One call on the `review` role with the evidence text, the diff and the rules. Returns `verdict` (approve, concerns, reject), `humanVisibleChange`, `addressesObservedFailure`, `minimal`, `notes`. It never changes the diff or the status; it is a second opinion the human reads before merging. Haiku by default; Sonnet is the recommended override here because judgement is where a stronger model earns its cost, and it is one call per fix.
6. **rematch** (opt-in, `rematch: true`), before anything leaves the machine. Install in the worktree, boot the patched store on a free port as a child process with a scrubbed environment (no API keys, no `GIT_*`), wait for `/health`, create a `Run` with `label: 'rematch'` and `parentRunId`, run the same agent with the mission's `storeUrl` overridden to the ephemeral store, stop the process, and store the `RunComparison`. This is the proof: a real rerun of the cheapest agent on the patched code, with its own evidence and report, viewable with the existing compare endpoint and before/after table. A fix whose rematch does not pass is not delivered.
7. **deliver.** `diff`: the diff is stored and served. `branch`: a worktree on the snapshot, `agentproof/<scenario>-<id>` branch, one commit authored `AgentProof <bot@agentproof.local>`, pushed with the request token through the git environment; the record gets the branch, commit and a `compareUrl` that opens GitHub's "open a pull request" page prefilled with the title and body. `pull_request`: the same push plus `POST /repos/{o}/{r}/pulls` with `draft: true` and the rendered Markdown as the body. Branch names are validated against `^agentproof/[a-z0-9][a-z0-9._-]{0,60}$` before any git command.

**Cost control.** The model sees a bundle of about 2k to 3k tokens of evidence and at most about 4k tokens of source, twice at most, plus one review call. A fix costs cents on Haiku. There is no "orchestrator model": sequencing, selection and verdicts are code, which is cheaper and deterministic. The reports already compress the run; the pipeline never reads a trace or a screenshot.

## 4. The record

`CodeFix` in `packages/shared/src/codefix.ts`. Highlights:

| Field                    | Written by | What a frontend does with it                                                                 |
| ------------------------ | ---------- | -------------------------------------------------------------------------------------------- |
| `status`, `stage`        | code       | Running, succeeded or failed, and where it is: drives a stepper                              |
| `input`                  | code       | What failed (observed), the attribution prior, the exact evidence text the model received    |
| `localization[]`         | code       | Ranked files with matched terms and whether the full text went to the model                  |
| `attempts[]`             | mixed      | Each attempt: model, proposal (inferred), diff (code), edit errors (code), validation (code) |
| `attempts[i].validation` | code       | Check table: id, passed/failed/skipped, factual detail, duration                             |
| `finalAttempt`           | code       | Which attempt produced the deliverable diff                                                  |
| `review`                 | model      | Advisory verdict with notes, rendered as "second opinion", never as a status                 |
| `delivery`               | code       | Mode, branch, commit, compare URL, PR URL and number, draft flag, error                      |
| `rematch`                | code       | The rematch run id and the before/after `RunComparison`                                      |
| `usage`                  | code       | Tokens and estimated cost across every model call                                            |
| `timeline[]`             | code       | Timestamped stage messages for a live log                                                    |
| `artifacts[]`            | code       | `codefix/<id>/codefix.json`, `codefix.md`, `patch.diff` under `data/artifacts`               |

The Markdown rendering (`renderCodeFixMarkdown`) is the PR body and the `codefix.md` artifact: observed failure, hypothesis (labelled), the diff, the validation table, the review (labelled), the rematch result, cost, and the sentence "Opened as a draft by AgentProof. A human reviews and merges; the agent cannot."

## 5. Self-validation ladder

| Check                   | How                                                                             | Fails when                                                              |
| ----------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `paths_in_scope`        | every touched path is relative, inside `<storeRoot>/src`, allowlisted extension | any `..`, absolute path, non-source file, path outside the store root   |
| `no_dependency_changes` | touched paths                                                                   | `package.json`, lockfiles, `.github/`, `.env*`, scripts, Dockerfiles    |
| `size_within_bounds`    | diff stats                                                                      | more than 5 files or 300 changed lines                                  |
| `applies_cleanly`       | `git apply --check` in a fresh worktree at the snapshot commit                  | any hunk fails                                                          |
| `typecheck`             | `npm ci --ignore-scripts && tsc --noEmit` in the store root                     | tsc exits non-zero; `skipped` when the repo has no lockfile or tsconfig |
| `rematch`               | the same agent on the patched store (opt-in)                                    | the rematch run does not pass, or regresses a checkpoint                |

Ryan's grader (`docs/storefront/verify-scenarios.mjs`) stays outside the agent as the external oracle: FIXED, no HUMAN BROKEN, control OK, right file, minimal, compiles.

## 6. Threat model and mitigations

| Threat                                                                               | Where it enters                            | Mitigation (code unless stated)                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompt injection through page content (snapshots, the agent's own reasons, outcomes) | the evidence bundle                        | `sanitizeEvidenceText()` strips control, zero-width and bidi characters and cuts long lines; `scanUntrustedText()` records `evidenceFlags`; the text sits inside an `UNTRUSTED` fence keyed by a per-fix nonce that page content cannot predict; the system prompt states the trust boundary (prompt-level, first line only)                                                                                                                                                          |
| Prompt injection through repository content (comments, strings, docs)                | the source shown to the model              | Only `<storeRoot>/src/**` with a source-extension allowlist, regular files only (no symlinks or submodules), never `docs/`; every file is scanned: binary, oversized, invisible-character or credential-bearing files are excluded and can never be edited; instruction-like files are shown fenced and flagged in `localization[].flags`; source is never altered, so the model's search strings still match                                                                         |
| Malicious or over-reaching model output into the repository                          | the diff                                   | Output bounded by Zod (edit count, lengths); edits must target a file shown in full with a unique verbatim match; `paths_in_scope`, `no_dependency_changes`, `size_within_bounds`; `content_policy` rejects external URLs, network calls, dynamic code, process or filesystem access, script injection, obfuscation, invisible characters, secrets, new package imports, CSS that hides controls, and removed payment guards; then `git apply --check`, `tsc`, and the opt-in rematch |
| Model output into humans and other bots (PR title and body, headlines)               | the Markdown record                        | Model-written text is HTML-escaped, stripped of invisible characters and capped (`escapeModelText()`); the record labels every model field as a hypothesis; the evidence text is inside a collapsed fenced block                                                                                                                                                                                                                                                                      |
| Credential exposure                                                                  | git, npm, the store process, logs, records | Tokens are request-scoped or minted per operation and never persisted; git receives them only through the environment; child processes get an allowlisted environment with no `*KEY*`, `*TOKEN*`, `GIT_*` or `npm_config_*`; the app's private key is read from env or a 0600 file and never rendered; `GET /github/app` describes the app without it; errors never echo tokens                                                                                                       |
| Repository code execution                                                            | connect, localize, validate, rematch       | Bare clone, `git show` and `git worktree` for reads; `npm ci --ignore-scripts`; hooks disabled on every git call; the rematch is opt-in, loopback-only, time-boxed and killed afterwards                                                                                                                                                                                                                                                                                              |
| Destructive or unauthorized GitHub actions                                           | the GitHub client and git                  | Operation allowlist (no merge, approve, ready-for-review, delete or default-branch write can be expressed); pushes only to `agentproof/*`, never forced; pull requests always drafts; the app asks for the minimum permissions and each token is scoped to one repository                                                                                                                                                                                                             |
| Runaway cost or time                                                                 | the loop                                   | At most `maxAttempts` (default 2) plus one file-request round; token caps per call; a 120 s model timeout, 60 s git, 180 s install, 120 s typecheck, 45 s store boot, 10 min rematch; one fix per run at a time                                                                                                                                                                                                                                                                       |
| Auditability                                                                         | the record                                 | `input.evidenceText` is the exact evidence; `attempts[].promptSha256` and `promptChars` fingerprint the exact prompt; every attempt, check, flag and credential kind (`delivery.actor`, `RepositoryConnection.accessVia`) is stored; artifacts hold the JSON, Markdown and patch                                                                                                                                                                                                      |

## 8. Build order

1. **P0, the diff path.** Shared schema, the pure modules, prompts, orchestrator through `validate` and `review`, routes, DB, events, script, docs. Demo: connect the store repo to a failed Alpha run on A, run the fix, show the record and the diff. Grade the diff with the grader on an export.
2. **P1, delivery.** `branch` and `pull_request` modes with the PAT; draft PR with the rendered body. Demo: the PR appears on GitHub as a draft from the agent.
3. **P2, proof and provenance.** The opt-in rematch against the patched worktree store; the GitHub App credential (built: see section 2); the hardening in section 6.

If time runs short: P0 alone already gives the dashboard a diff with a code-written validation table, which is the trust story. Hand-applied reference patches through the same validation path are the fallback, labelled on screen.

## 9. Running it

```bash
pnpm dev:store && pnpm dev:runner
node scripts/run-mission.mjs --bug A --agents alpha                      # a failed Alpha run
# connect the store repository to that run (dashboard, or curl POST /runs/<id>/repository)
node scripts/codefix.mjs --run <runId>                                  # diff mode, prints the record
node scripts/codefix.mjs --run <runId> --mode pull_request --token-env GITHUB_TOKEN --store-root apps/storefront
```

`--store-root` is the directory of the store inside the repository (`apps/storefront` for this monorepo, empty for the exported `northwind-storefront`). Nothing outside it is read or written.
